# Platform setup

Read for a missing R or RStudio, not for ordinary plotting. Check current official release, installer and system requirements at use time; package IDs, versions and support change. Never hard-code another user's paths. Before changes show detected system, intended software, install locations and chosen versions; follow the user's stated version preference.

- macOS: discover `/usr/local/bin`, `/opt/homebrew/bin`, `/Library/Frameworks/R.framework`, and Applications as well as PATH. Use official [CRAN macOS](https://cran.r-project.org/bin/macosx/) Apple Silicon/Intel installer and [Posit downloads](https://posit.co/download/rstudio-desktop/) matching the OS. Official signed R installer commonly requires administrator interaction. Check `pkgutil --check-signature`; for a disk image verify checksum if published, mount read-only, verify application signature and install into the user's requested location. If admin credentials are required, hand off to the user. Homebrew is an option if already installed and user policy permits; do not install it merely to set up R unless requested.
- Windows: detect R via PATH and installed application/registry locations, and check RStudio. Prefer official [CRAN Windows](https://cran.r-project.org/bin/windows/base/) and [Posit downloads](https://posit.co/download/rstudio-desktop/), or an already available reputable package manager after verifying exact package identity. Follow installer version-specific silent-install options; do not assume all releases use the same switches. Handle User Account Control by user handoff. Check signatures and architecture before running downloaded installers.
- Linux: determine distribution, version and architecture (`/etc/os-release`, `uname -m`) and whether a desktop is present. Use the matching supported [CRAN Linux instructions](https://cran.r-project.org/bin/linux/) or distribution repository for R and [Posit desktop installer](https://posit.co/download/rstudio-desktop/) for the supported distro/architecture. User must handle any administrator authentication. On headless hosts, set up R and packages and explicitly report desktop RStudio as not installed/tested unless an appropriate server setup was requested.

Verify R with `Rscript --version` and a basic calculation; check the IDE is present and starts if desktop and permissions permit. Check whether a pre-existing IDE points at a different R. Shell and IDE may have different PATH and libraries; validate each separately. If a verified old release is unavailable, prefer a supported stable release only in accordance with user instructions; disclose the fallback. Do not bypass macOS Gatekeeper, OS trust warnings, or TLS validation.
